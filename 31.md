# NUT-31: Mint and melt fees

`optional`

`depends on: NUT-04 NUT-05 NUT-06 NUT-23`

---

This document defines two mint-charged fees for the value-carrying operations
that cross the mint boundary:

| Direction | Operation | Fee |
|---|---|---|
| in (`dovnitř`) | mint (pay-in) | `mint_fee` |
| out (`ven`) | melt (payout) | `melt_fee` |

Both are a proportion of the operation `amount`, kept by the mint. They are the
in/out counterparts of the existing within-mint swap fee ([NUT-02][02]
`input_fee_ppk`), which is **out of scope** here and unchanged: the swap fee is a
per-input cost that a wallet computes offline from the keyset, whereas these two
fees are quote-time prices disclosed before the wallet commits.

A fee under this NUT is distinct from the Lightning `fee_reserve` of
[NUT-05][05]: the reserve is a refundable routing budget returned to the wallet
as change ([NUT-08][08]); a `mint_fee`/`melt_fee` is kept by the mint and never
returned.

## Rate unit

Both rates are expressed in **basis points (bps)** of the operation `amount`,
denominated in the method's `unit`. `1 bps = 0.01%`, `100 bps = 1%`,
`10000 bps = 100%`. The fee amount is rounded **up**:

```python
def fee(amount: int, bps: int) -> int:
    return (amount * bps + 9999) // 10000   # ceil(amount * bps / 10000)
```

Integer arithmetic only; floating point **MUST NOT** be used, to keep the result
deterministic. A rate of `0` (or an absent advertisement) means the fee is not
charged and this NUT is a no-op for that operation.

## Advertisement (NUT-06)

A mint advertises its rates per method-unit in the [NUT-06][06]
`GetInfoResponse.nuts` object, inside the `options` of the existing
`MintMethodSetting` / `MeltMethodSetting` entries (the same slot [NUT-23][23]
uses for `description` and `amountless`):

```json
"4": {
  "methods": [
    { "method": "bolt11", "unit": "sat", "options": { "fee_bps": 100 } }
  ],
  "disabled": false
},
"5": {
  "methods": [
    { "method": "bolt11", "unit": "sat", "options": { "fee_bps": 100 } }
  ],
  "disabled": false
}
```

A mint MAY also advertise `"31": { "supported": true }`. The advertised rate is a
discovery hint; the **binding** price for a specific operation is always the
absolute `mint_fee` / `melt_fee` returned in the quote (below), which the wallet
reads and MUST be willing to pay before committing.

## Mint fee (pay-in)

Extends the mint flow of [NUT-04][04] / [NUT-23][23]. When the mint charges a
mint fee, the payment request collects `amount + mint_fee`, but only `amount` is
credited as mintable ecash; the mint keeps `mint_fee`. The
`PostMintQuoteBolt11Response` gains a `mint_fee` field (in `unit`):

```json
{
  "quote": <str>, "request": <str>, "amount": <int>, "mint_fee": <int>,
  "unit": <str_enum[UNIT]>, "method": "bolt11",
  "amount_paid": <int>, "amount_issued": <int>, "updated_at": <int>,
  "expiry": <int|null>
}
```

- `mint_fee = ceil(amount * fee_bps / 10000)`.
- `amount` is the mintable ecash (unchanged meaning). For `bolt11`, the invoice
  `request` is for `amount + mint_fee`.
- On payment the mint MUST credit only `amount` to `amount_paid` (never
  `amount + mint_fee`), so the mintable balance stays `amount_paid -
  amount_issued` and the [NUT-04][04] rule `sum(outputs) <= amount_paid -
  amount_issued` is unchanged. The mint keeps `mint_fee`.

**Example** (`fee_bps = 100`, i.e. 1%): request `amount = 1000 sat` →
`mint_fee = 10`, invoice for `1010 sat`. After payment `amount_paid = 1000`; the
wallet mints up to `1000` sat of ecash; the mint keeps `10 sat`.

## Melt fee (payout)

Extends the melt flow of [NUT-05][05] / [NUT-23][23]. The
`PostMeltQuoteBolt11Response` gains a `melt_fee` field alongside `fee_reserve`:

```json
{
  "quote": <str>, "request": <str>, "amount": <int>,
  "fee_reserve": <int>, "melt_fee": <int>,
  "unit": <str_enum[UNIT]>, "method": "bolt11",
  "state": <str_enum[STATE]>, "expiry": <int>, "payment_preimage": <str|null>
}
```

- `melt_fee = ceil(amount * fee_bps / 10000)`, kept by the mint on success.
- The amount the mint enforces at melt time becomes:

```
sum(inputs) >= amount + fee_reserve + melt_fee + input_fee
```

where `input_fee` is the [NUT-02][02] swap fee for the provided inputs.
- `fee_reserve` remains refundable via [NUT-08][08]; `melt_fee` is excluded from
  the change calculation (deducted before it), so [NUT-08][08] is unchanged in
  shape and still returns only unused routing reserve.

**Example** (`fee_bps = 100`): a `bolt11` invoice `amount = 1000 sat`,
`fee_reserve = 10`, `input_fee = 0` → `melt_fee = 10`; the wallet funds
`>= 1020 sat`. If routing costs `2 sat`, the mint keeps `melt_fee = 10` and
returns `fee_reserve - 2 = 8 sat` as change. `melt_fee` never comes out of the
reserve.

## Edge cases

- **Internal settlement** (a melt settled against a mint quote of the same mint,
  no routing): fee-free (`melt_fee = 0`), consistent with `fee_reserve = 0`.
- **Partial (MPP) payments** ([NUT-15][15]): `melt_fee` is computed on the
  quote's `amount` (the partial amount), once per quote, kept once — never
  per shard.
- **Amountless invoices**: `melt_fee` is computed on the wallet-supplied amount.

## Backwards compatibility

Adding `mint_fee` / `melt_fee` to quote responses and `fee_bps` to method
`options` is additive. A wallet that does not implement this NUT ignores the new
fields; it then under-funds a melt (rejected by the mint) or cannot attribute a
larger-than-`amount` mint invoice. It cannot lose funds — the fee is always
disclosed in the quote before the wallet commits. Mints SHOULD keep `fee_bps` at
`0` until the wallets they serve implement this NUT, and SHOULD advertise the
rate so wallets can display the true price.
